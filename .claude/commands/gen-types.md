# 任務：依規格產生型態/介面定義檔

## 目標檔案
規格檔案路徑：$ARGUMENTS
若未指定路徑，預設在 `specs/` 目錄下尋找唯一的規格 .md 檔案。

## 執行步驟

1. 讀取目標規格檔案，定位標題文字包含「資料契約」或「Data Contracts」的章節
   （**不要**依章節編號定位，因為不同專案的章節編號可能不同；只認標題文字）。

2. 若找不到符合此標題的章節，停止執行並回報：
   「找不到『資料契約』章節，請確認規格檔案是否依專案模板 `specs/_template.md` 撰寫。」

3. 解析該章節內每一個資料結構表格，取得：
   - 結構名稱（如 Entry、Category）
   - 每個欄位的名稱、型態、必填與否、額外約束

4. 依專案現有技術棧產生對應型態定義：
   - 若專案為 TypeScript，於 `src/types/` 下為每個結構建立對應的 interface，
     必填欄位不可標記為 optional；有明確約束（如長度限制、列舉值）需以型態
     或註解明確表達，命名需與規格文件的欄位名稱完全一致（不可自行改寫）。
   - 若專案為 Python，於對應目錄下使用 Pydantic model 表達，規則同上。
   - 若專案技術棧尚未決定，停止執行並詢問使用者。

5. 型態檔生成後，立即執行型態檢查：
   - 等待 hook 自動驗證，若 hook 回報錯誤則修正。

6. 完成後，簡短列出本次產生的檔案路徑與涵蓋的資料結構清單，
   並註明型態檢查結果（通過/失敗）。

## 限制
- 僅處理「資料契約」章節內容，不得依此指令內容延伸實作其他功能模組。
- 不得修改規格文件本身。
- 不得自行新增規格文件未定義的欄位或結構。
