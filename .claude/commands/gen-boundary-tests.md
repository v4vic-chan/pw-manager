# 任務：產生跨層邊界測試（Layer Boundary Test）

## 用詞說明
本指令產生的不是傳統 consumer-driven contract test（該概念用於獨立部署服務之間）。
本專案為單一 App 內的分層架構，此處驗證的是「資料契約在跨層傳遞時形狀是否保持一致」，
稱為跨層邊界測試（Layer Boundary Test），不得與微服務 API contract test 混用術語。

## 目標檔案
規格檔案路徑：$ARGUMENTS
若未指定路徑，預設在 `specs/` 目錄下尋找唯一的規格 .md 檔案。

## 執行步驟

1. 讀取目標規格檔案，定位標題文字包含「系統架構總覽」的章節，取得該專案的分層
   定義（例如 UI 層、應用邏輯層、加密層、儲存層等，層數與名稱依專案不同而異，
   **不要**假設固定的層數或層名）。

2. 定位標題文字包含「資料契約」或「Data Contracts」的章節，取得跨層傳遞的
   核心資料結構定義（欄位、型態、必填、約束）。

3. 若上述任一章節找不到，停止執行並回報：
   「找不到對應章節，請確認規格檔案是否依專案模板 `specs/_template.md` 撰寫。」

4. 依偵測到的層與層之間的相鄰關係，針對每一組邊界產生對應測試，測試內容依
   規格描述決定，包含但不限於：
   - 資料型態在跨層傳遞前後是否與型態定義檔（`src/types/` 下對應檔案）完全一致
   - 若規格中某層明確涉及加解密（例如標題或內容包含「加密層」「Crypto」等字樣），
     必須額外產生加解密往返一致性測試（round-trip test）：
     明文輸入 → 加密 → 解密 → 比對輸出與原始明文完全相同
   - 若某層邊界涉及必填欄位遺失、格式錯誤等異常輸入，需包含至少一個異常情境測試

   **實作先行檢查（不得詢問使用者，依此規則自動處理）**：
   產生測試前，先檢查該測試所依賴的層是否已存在可呼叫的實作程式碼
   （例如加解密往返測試需要 Crypto Layer 的 encrypt/decrypt 函式已存在）。
   - 若依賴的實作已存在：正常產生可執行測試。
   - 若依賴的實作尚不存在：仍產生該測試案例，但標記為 `test.skip`
     （或對應測試框架的等效跳過語法），並在測試上方加註解說明：
     跳過原因（依賴哪個尚未實作的模組/函式）、解除條件（該模組實作完成後移除 skip）。
   - 不受實作缺席影響的測試（如純型態形狀比對、資料結構層級的異常情境）
     仍應正常產生為可執行測試，不得一併標記 skip。

5. 依專案現有技術棧產生對應測試檔語法：
   - TypeScript 專案：使用專案既有測試框架（優先偵測 `package.json` 內已安裝的
     Jest 或 Vitest；若專案已採用 Vite 作為建置工具但尚無測試框架，預設採用
     Vitest，因其與 Vite 生態整合成本最低；若專案未使用 Vite 且無既有框架，
     才需詢問使用者），測試檔存放於 `tests/boundary/` 下，
     命名格式為 `<層A>-<層B>.boundary.test.ts`。
   - Python 專案：使用 pytest，測試檔存放於對應的 `tests/boundary/` 下。
   - 若技術棧本身尚未決定（規格 §2.1 技術棧選型留白），停止執行並詢問使用者。

6. 測試檔生成後，立即執行測試，確認：
   - 所有非 skip 的測試全數通過。
   - 所有 skip 的測試皆有明確的跳過原因與解除條件註解。
   - 等待 hook 自動驗證（若專案已設定對應的 PostToolUse 測試 hook），
     若尚未設定，則直接執行測試指令並回報結果，非 skip 測試失敗需修正至通過為止。

7. 完成後，簡短列出本次產生的測試檔路徑、涵蓋的層邊界、可執行測試數與
   skip 測試數（並列出各自對應的待完成實作項目）。

## 限制
- 僅處理跨層邊界的資料一致性驗證，不得延伸測試單一層內部的業務邏輯細節
  （那屬於單元測試範疇，非本指令職責）。
- 不得修改規格文件本身。
- 不得自行假設規格文件未明確定義的層或資料結構。
- 不得為了讓測試「可執行」而在測試檔內一併撰寫 Crypto/Service/Storage 等
  層級的最小實作，此舉超出本指令職責範圍。
